IONOS Cloud Backup einrichten – Anleitung für Windows

Viva-Deluxe Betriebs-App · Sicherung außerhalb des Servers · Stand 11.10.2026 · Dauer ca. 45 Minuten

Worum geht es? Die App sichert sich jede Nacht um 02:30 selbst nach /opt/viva-sicherung (Datenbank + alle Dateien). Diese Sicherung liegt aber auf demselben Server. Fällt der Server aus, wird gehackt oder versehentlich gelöscht, ist auch die Sicherung weg. IONOS Cloud Backup (Acronis Cyber Protect) kopiert die Sicherung jede Nacht in ein Rechenzentrum außerhalb des Servers.
WasWo auf dem ServerWie oft geändert
Datenbank (alle Kunden, Rechnungen, Zeiten …)/opt/viva-sicherung/datenbank_*.dumptäglich neu
Dateien (Belege, PDFs, Uploads, Archiv)Docker-Speicher …/volumes/deploy_daten/_data (Schritt 6)nur neue kommen dazu
Zugangsdaten der App/opt/viva/deploy/.env.liveselten

Die Dateien sichern wir direkt aus dem Docker-Speicher statt aus den täglichen dateien_*.tar.gz: Die ZIP-Pakete sind jeden Tag komplett neu und würden den Cloud-Speicher (z. B. Starter 100 = 100 GB) in wenigen Wochen füllen. Direkt gesichert überträgt Acronis nach dem ersten Mal nur noch die neuen Dateien.

Niemals in den Chat schicken: Registrierungstoken, Verschlüsselungs-Passwort der Sicherung, root-Passwort. Das Verschlüsselungs-Passwort ausdrucken und in den Tresor legen – ohne es ist die Sicherung wertlos, IONOS kann es nicht wiederherstellen.

1Backup-Konsole öffnen

  1. IONOS-Kundenkonto → Server & Cloud → Cloud Backup → beim gebuchten Paket „Backup-Konsole öffnen“ (Rechenzentrum Europa, nicht USA – Datenschutz).
  2. Es öffnet sich die Acronis-Oberfläche „Cyber Protect“. Die Adresse oben im Browser merken (z. B. https://eu2-cloud.acronis.com – wird ggf. bei der Installation abgefragt).

2Agent-Datei und Registrierungstoken holen

  1. In der Konsole: Geräte → Hinzufügen (oben rechts, „+ Gerät hinzufügen“).
  2. Unter „Server“ Linux wählen → die Datei CyberProtect_AgentForLinux_x86_64.bin (ca. 1,2 GB) wird in den Ordner Downloads geladen. (Schon erledigt? Dann weiter.)
  3. Auf derselben Seite unten: „Registrierungstoken erzeugen“ (bzw. „Über Registrierungstoken registrieren“) → Gültigkeit z. B. 1 Tag → Erzeugen → Token kopieren (Form XXXX-XXXX-XXXX). In die Notiz einfügen.

3Datei auf den Server hochladen (Windows)

Die Datei CyberProtect_AgentForLinux_x86_64.bin liegt im Ordner Downloads.

  1. Windows-Taste drücken, powershell tippen, Windows PowerShell öffnen (blaues Fenster).
  2. Prüfen, ob die Datei gefunden wird – eingeben und Enter: 
    dir "$env:USERPROFILE\Downloads\*Cyber*"
    Es erscheint eine Zeile mit dem Dateinamen und einer Größe um 1.200.000.000. Steht der Name anders da (z. B. … (1).bin), im nächsten Befehl genau diesen Namen verwenden.
  3. Hochladen – eingeben und Enter: 
    scp "$env:USERPROFILE\Downloads\CyberProtect_AgentForLinux_x86_64.bin" root@217.160.236.117:/root/agent.bin
    • Erste Verbindung: Frage „Are you sure you want to continue connecting“ → yes tippen, Enter.
    • root-Passwort des Servers eingeben (beim Tippen erscheint nichts – das ist normal), Enter.
    • Es läuft eine Prozentanzeige. Bei 1,2 GB je nach Leitung 5–30 Minuten. Fenster offen lassen, PC nicht in den Ruhezustand.
    Tipp: Statt den Pfad zu tippen: scp (mit Leerzeichen) schreiben, die Datei aus dem Explorer ins PowerShell-Fenster ziehen, dann root@217.160.236.117:/root/agent.bin anhängen.
Fehler „No such file or directory“: Dateiname oder Ordner stimmt nicht – Schritt 2 wiederholen und den angezeigten Namen genau übernehmen.
„Permission denied“: root-Passwort falsch.
„Connection timed out“: Internet/Firma-WLAN blockiert Port 22 – anderes Netz (z. B. Handy-Hotspot) probieren.

4Mit dem Server verbinden und vorbereiten

Im selben PowerShell-Fenster (oder einem neuen):

ssh root@217.160.236.117

root-Passwort eingeben. Die Zeile beginnt jetzt mit root@…:~# – du bist auf dem Server. Dann nacheinander:

ls -lh /root/agent.bin              # muss ca. 1.2G zeigen
df -h /root                         # Spalte „Avail“: mindestens 4G frei?
apt update
apt install -y dkms gcc make perl linux-headers-$(uname -r)

Die letzte Zeile dauert 1–3 Minuten. Meldet sie „Unable to locate package linux-headers-…“: egal, weiter.

Einfügen in PowerShell: Rechtsklick ins Fenster. Kopieren: Text mit der Maus markieren, Rechtsklick.

5Agent installieren

cd /root
chmod +x agent.bin
./agent.bin

Es erscheint ein blaues Text-Menü (Bedienung: Pfeiltasten, Leertaste = ankreuzen, Tab = zu den Knöpfen, Enter = weiter):

  1. Komponenten: „Agent for Linux“ ist angekreuzt → Weiter. Sonst nichts ankreuzen.
  2. Der Installer prüft/baut das SnapAPI-Modul (dauert etwas). Fragt er, ob er fehlende Pakete installieren soll → Ja.
  3. Registrierung: „Mit Registrierungstoken registrieren“ (bzw. „Use registration token“) wählen.
    • Serveradresse: die Adresse aus Schritt 1 (z. B. https://eu2-cloud.acronis.com), falls gefragt.
    • Token aus Schritt 2 eintippen.
  4. „Installation erfolgreich“ → Beenden.

Prüfen und aufräumen:

systemctl status acronis_mms --no-pager | head -5   # „active (running)“
rm /root/agent.bin                                 # gibt 1,2 GB frei

In der Konsole unter Geräte erscheint nach 1–3 Minuten der Server mit grünem Punkt. Optional umbenennen in „Viva App-Server“.

6Pfad des Datei-Speichers herausfinden

docker volume inspect deploy_daten --format '{{ .Mountpoint }}'

Ergebnis ist normalerweise /var/lib/docker/volumes/deploy_daten/_data. Diesen Pfad brauchst du gleich. (Kommt „no such volume“: docker volume ls eingeben und den Namen nehmen, der auf _daten endet.)

7Schutzplan anlegen

Konsole → Geräte → Server anklicken → Schützen → Plan erstellen (bzw. „+ Plan erstellen“). Name: Viva täglich.

Erstellen bzw. Anwenden klicken. Danach im Plan „Jetzt ausführen“. Die erste Sicherung überträgt alles und kann je nach Datenmenge 15–90 Minuten dauern; die folgenden nur noch die Änderungen.

8Test-Wiederherstellung (wichtig!)

Eine Sicherung, die nie zurückgeholt wurde, ist keine Sicherung. Nach der ersten erfolgreichen Sicherung:

  1. Konsole → Geräte → Server → Wiederherstellung → neuesten Wiederherstellungspunkt wählen → Dateien/Ordner wiederherstellen.
  2. Unter /opt/viva-sicherung die neueste datenbank_….dump ankreuzen → Wiederherstellen.
  3. Wichtig: „Ziel“ ändern auf „Benutzerdefinierter Speicherort“ → /root/test-wiederherstellung (niemals über die Originaldateien!). Verschlüsselungs-Passwort eingeben → Jetzt starten.
  4. Auf dem Server prüfen, ob die Datei lesbar ist: 
    ls -lh /root/test-wiederherstellung/opt/viva-sicherung/
cd /opt/viva/deploy
docker compose --env-file .env.live exec -T db pg_restore --list \
  < /root/test-wiederherstellung/opt/viva-sicherung/datenbank_*.dump | head -5
    Erscheinen Zeilen wie „; Archive created at …“ und „dbname: viva“, ist die Sicherung in Ordnung.
  5. Genauso eine einzelne Datei aus …/deploy_daten/_data (z. B. ein PDF unter archive/) wiederherstellen.
  6. Aufräumen: rm -rf /root/test-wiederherstellung

Test-Wiederherstellung alle 6 Monate wiederholen (Termin im Kalender eintragen).

9Benachrichtigungen

Konsole → oben rechts Benutzer → Benachrichtigungen (bzw. Einstellungen → E-Mail-Benachrichtigungen): an info@ oder deine Adresse, angehakt: Fehler und Warnungen bei Backups, „Gerät offline“. Erfolgsmeldungen nicht nötig.

Zusätzlich meldet die App selbst, wenn die nächtliche Sicherung auf dem Server fehlt (Einstellungen → Systemzustand).

Ernstfall: Server komplett weg

  1. Neuen IONOS-VPS (Ubuntu 24.04) bestellen, App wie bei der ersten Installation mit deploy/install.sh einrichten (Domain-DNS auf die neue IP umstellen).
  2. Acronis-Agent wie oben (Schritte 2–5) auf dem neuen Server installieren und registrieren.
  3. Aus der Konsole die Sicherung des alten Geräts nach /root/rueck auf den neuen Server wiederherstellen (Speicherort „Cloud-Speicher“ → altes Gerät → Ziel: neuer Server, Ordner /root/rueck).
  4. Datenbank, Dateien und .env.live einspielen – diesen Schritt mit mir zusammen machen, damit nichts überschrieben wird, was schon da ist.

Störungen

MeldungWas tun
„SnapAPI module could not be built/loaded“Für unsere Sicherung (Dateien/Ordner) nicht schlimm – der Agent sichert dann ohne Snapshot. Installation trotzdem fortsetzen. Wer es beheben will: apt install -y linux-headers-$(uname -r) dkms, dann ./agent.bin erneut starten → „Reparieren“.
„Unable to locate package linux-headers-…“IONOS-Kernel ohne passende Header; ignorieren (siehe Zeile darüber).
scp: „No such file or directory“Dateiname/Ordner prüfen (Schritt 3, Befehl dir).
„Registration failed“ / Token ungültigToken abgelaufen oder vertippt → neuen Token erzeugen. Neu registrieren: /usr/lib/Acronis/RegisterAgentTool/RegisterAgent -o register -t cloud -a https://<Konsole> --token <TOKEN>
„No space left on device“ beim Downloaddf -h prüfen; alte Datei rm /root/agent.bin; ggf. Docker aufräumen docker image prune -f.
Gerät in der Konsole „offline“systemctl restart acronis_mms aakore; Firewall lässt ausgehende Verbindungen zu (ufw sperrt nur eingehende) – nichts freigeben nötig.
Speicher fast voll (Konsole)Aufbewahrung auf 30 Tage ohne Wochen/Monate kürzen oder größeres Paket buchen.

Checkliste

  • Agent installiert, Gerät in der Konsole grün
  • agent.bin gelöscht
  • Schutzplan „Viva täglich“: drei Pfade, Ausschluss dateien_*.tar.gz, 04:00, Cloud-Speicher, verschlüsselt
  • Verschlüsselungs-Passwort ausgedruckt im Tresor
  • Erste Sicherung erfolgreich (grüner Haken)
  • Test-Wiederherstellung Datenbank + eine Datei geklappt, Testordner gelöscht
  • E-Mail-Benachrichtigung bei Fehlern eingerichtet
  • Termin „Test-Wiederherstellung“ in 6 Monaten im Kalender
  • AVV mit IONOS abgeschlossen (Kundenkonto → Datenschutz → Auftragsverarbeitung)
