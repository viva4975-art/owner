Nächste Schritte – Server fertig absichern

Viva-Deluxe Betriebs-App · https://app.viva-deluxe-reinigung.de · Stand 11.10.2026 · Reihenfolge einhalten, jeder Schritt ca. 5–15 Minuten

Niemals in den Chat schicken: Passwörter, Tokens, Verschlüsselungs-Passwort, Inhalt der .env.live. Fehlermeldungen und Screenshots ohne diese Angaben sind in Ordnung.
Schon erledigt: Acronis-Agent installiert und angemeldet, erste Sicherung der kompletten Maschine erfolgreich (11.10.2026).

1Aufräumen nach der Anmeldung

  1. Auf dem Server das Passwort aus dem Befehlsverlauf löschen: 
    history -c && history -w
  2. In der Backup-Konsole (Acronis) die beiden im Chat geschickten Registrierungstokens löschen (Geräte → + Hinzufügen → ganz unten „Registrierungstoken“ → Liste/Verwalten → löschen). Falls nicht auffindbar: sie laufen von selbst ab.

2Sicherung: täglich und verschlüsselt

Der Standard-Plan „Backup entire workload“ sichert nur Mo–Fr und unverschlüsselt. Auf dem Server liegen Personaldaten (Steuer-ID, SV-Nummer, IBAN, Krankmeldungen) → eigener, verschlüsselter Plan.

  1. Backup-Konsole → Geräte → ubuntu anklicken → oben rechts „Plan hinzufügen“ → „Plan erstellen“.
  2. Name: Viva täglich.
  3. Was sichern: Komplette Maschine · Wohin: Cloud Storage.
  4. Planung: täglich, alle 7 Tage (Mo–So), 04:00 (nach der App-Sicherung um 02:30).
  5. Aufbewahrung: 90 Backups (oder 90 Tage) – falls der gebuchte Speicher knapp wird: 30.
  6. Verschlüsselung: AN, AES-256, eigenes Passwort.
    Passwort sofort sicher aufschreiben (Passwort-Manager oder Papier im Tresor, am besten zwei Stellen). Ohne dieses Passwort kann niemand – auch IONOS nicht – die Sicherung wiederherstellen.
  7. Alle anderen Module (Virenschutz, Patches, Überwachung …) ausschalten, falls angezeigt. → Erstellen.
  8. Beim neuen Plan „Jetzt ausführen“ → warten bis grün „Backup erfolgreich abgeschlossen“ (erstes Mal dauert länger).
  9. Erst danach beim alten Plan „Backup entire workload“: … → Widerrufen (bzw. Entfernen). Die alte Sicherung bleibt nach der Aufbewahrungsregel erhalten.

3root-Passwort des Servers ändern

Das alte root-Passwort stand im Chat – daher neu setzen.

  1. Auf dem Server (angemeldet als root): 
    passwd
  2. Neues Passwort zweimal eintippen (es wird beim Tippen nicht angezeigt – das ist normal). Mind. 16 Zeichen.
  3. Meldung password updated successfully. Passwort im Passwort-Manager speichern.
  4. Test: Verbindung trennen (exit) und mit dem neuen Passwort neu anmelden – erst dann das alte Fenster schließen.
Falls die Anmeldung über die IONOS-KVM-Konsole läuft: dort gilt ebenfalls das neue Passwort. Das IONOS-Kundenkonto-Passwort ist etwas anderes und bleibt.

4Mailzugang eintragen (falls noch nicht geschehen)

  1. Datei öffnen: 
    nano /opt/viva/deploy/.env.live
  2. Zeilen ergänzen bzw. vorhandene ändern (Wert immer in einfachen Hochkommas, ohne Leerzeichen um =): 
    SMTP_HOST='smtp.exchange2019.ionos.de'
SMTP_PORT='587'
SMTP_USER='buchhaltung@viva-deluxe-reinigung.de'
SMTP_PASS='Passwort des Postfachs'
MAIL_FROM='buchhaltung@viva-deluxe-reinigung.de'
ALERT_EMAIL='ahmed@viva-deluxe-reinigung.de'
    ALERT_EMAIL = wer Störungsmeldungen bekommt (gern Ihre eigene Adresse).
  3. Speichern: Strg+O, Enter, Beenden: Strg+X.
  4. App neu starten: 
    bash /opt/viva/deploy/update.sh
  5. Test in der App: Einstellungen → E-Mail-Versand prüfen → „Test-E-Mail senden“.
Solange APP_ENV='test' und MAIL_TEST_RECIPIENT gesetzt sind, gehen alle Mails nur an die Testadresse. Für den Echtversand an Kunden: APP_ENV='live' und die Zeile MAIL_TEST_RECIPIENT löschen – erst wenn die Test-Mail ankommt.

5Wächter von außen: UptimeRobot (App erreichbar?)

  1. uptimerobot.com → „Register for FREE“ → E-Mail bestätigen.
  2. „+ New monitor“ → Typ Keyword.
  3. URL: https://app.viva-deluxe-reinigung.de/health/voll
  4. Keyword: ok · „Alert when keyword does not exist“ · Intervall 5 Minuten.
  5. Benachrichtigung per E-Mail; zusätzlich die UptimeRobot-App aufs Handy (Push).
  6. Prüfen: Monitor zeigt grün „Up“.

6Wächter für die nächtliche Sicherung: healthchecks.io

  1. healthchecks.io → kostenloses Konto → „Add Check“: Name „Viva Sicherung“, Period 1 day, Grace 3 hours.
  2. Die Ping-Adresse kopieren (https://hc-ping.com/…).
  3. In /opt/viva/deploy/.env.live eine Zeile ergänzen (wie in Schritt 4): 
    BACKUP_PING_URL='https://hc-ping.com/…'
    Kein Neustart nötig – die Sicherung um 02:30 liest die Zeile selbst.
  4. Am nächsten Morgen: Check steht auf grün „Up“. Bleibt der Ping aus, kommt eine E-Mail.

7Kontrolle

  • App: Einstellungen → Systemzustand & Ausfallmeldung → „Jetzt prüfen“ → alles grün (Mail, Sicherung, Archiv-Kopie).
  • Acronis: Plan „Viva täglich“ grün, Verschlüsselung „Ein“, Planung Mo–So 04:00; alter Plan widerrufen.
  • UptimeRobot „Up“, healthchecks.io „Up“.
  • Neues root-Passwort und Backup-Verschlüsselungs-Passwort sicher abgelegt.

8Einmal im Quartal: Probe-Wiederherstellung

  1. Acronis: Gerät ubuntu → Wiederherstellung → jüngste Sicherung → Dateien/Ordner → /opt/viva-sicherung → eine datenbank_*.dump-Datei auswählen → Herunterladen (Verschlüsselungs-Passwort nötig).
  2. Lässt sich die Datei herunterladen, funktioniert die Sicherung. Datei danach wieder löschen (enthält Personaldaten).
Bei Problemen: Fehlermeldung bzw. Screenshot (ohne Passwörter/Tokens) schicken.
