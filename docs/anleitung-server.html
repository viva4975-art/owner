Server-Anleitung – Viva-Deluxe App

Server öffnen, Zugangsdaten eintragen, App neu starten, prüfen · IONOS VPS 217.160.236.117 · Stand 09.10.2026

Was ist „der Server“? Ein gemieteter Rechner bei IONOS (Rechenzentrum in Deutschland). Darauf laufen die App (https://app.viva-deluxe-reinigung.de), die Datenbank und die E-Rechnungs-Prüfung (KoSIT). Bedient wird er nur mit Textbefehlen. Für den Alltag brauchen Sie ihn nicht – nur, um Zugangsdaten einzutragen (Mail, Archiv) oder wenn etwas klemmt. Updates kommen automatisch alle 10 Minuten, Sicherungen jede Nacht um 02:30 Uhr.

1. Verbinden

Sie brauchen das root-Passwort des Servers (aus der IONOS-Bestellung bzw. Ihrem Passwort-Manager). Benutzername ist immer root.

Variante A – im Browser über IONOS (geht immer, auch ohne Programm)

  1. login.ionos.de öffnen und mit Ihrem IONOS-Kundenkonto anmelden.
  2. Menü → Server & Cloud → den Server mit der IP 217.160.236.117 anklicken.
  3. Oben rechts Aktionen → KVM-Konsole (heißt manchmal „Remote-Konsole“). Es öffnet sich ein schwarzes Fenster. Ist es leer, einmal Enter drücken.
  4. Bei login: → root eintippen, Enter.
  5. Bei Password: → root-Passwort eintippen, Enter. Beim Tippen erscheinen keine Zeichen und keine Sternchen – das ist normal.
  6. Sie sind drin, wenn vorne root@…:~# steht.
Achtung Tastatur in der KVM-Konsole: Die Konsole nutzt manchmal die amerikanische Tastatur. Dann sind Y und Z vertauscht und Sonderzeichen liegen woanders (z. B. ' auf der Ä-Taste, - auf ß). Klappt das Passwort nicht, liegt es oft daran. Bequemer ist Variante B/C (normale Tastatur, Kopieren/Einfügen geht).

Variante B – Windows (PowerShell)

  1. Windows-Taste drücken, PowerShell tippen, öffnen.
  2. Eingeben und Enter:
    ssh root@217.160.236.117
  3. Beim allerersten Mal fragt Windows „Are you sure you want to continue connecting?“ → yes tippen, Enter.
  4. root-Passwort eingeben (unsichtbar), Enter.

Einfügen in PowerShell: rechte Maustaste (nicht Strg+V). Markieren + Rechtsklick kopiert.

Variante C – Mac (Terminal)

  1. Cmd + Leertaste, Terminal tippen, öffnen.
  2. ssh root@217.160.236.117
    → yes (nur beim ersten Mal) → root-Passwort.

Variante D – Handy/iPad (nur für Notfälle)

App Termius (iOS/Android, kostenlos) → „New Host“ → Adresse 217.160.236.117, Benutzer root, Passwort → verbinden. Am Handy ist Tippen mühsam – lieber am PC.

2. Bedienung im schwarzen Fenster

  • Befehl eintippen (oder einfügen) und mit Enter abschicken. Groß-/Kleinschreibung und Leerzeichen genau übernehmen.
  • Läuft etwas und Sie wollen abbrechen: Strg + C.
  • Pfeil ↑ holt den letzten Befehl zurück.
  • Zeilen, die in dieser Anleitung mit # beginnen, sind nur Erklärungen – nicht eintippen.
  • Verbindung beenden: exit (die App läuft weiter).

3. Zugangsdaten eintragen (Mail, später Archiv)

Alle Passwörter und Schlüssel stehen nur in einer Datei auf dem Server: /opt/viva/deploy/.env.live. Nie in den Chat, nie in eine E-Mail.

  1. Datei öffnen:
    nano /opt/viva/deploy/.env.live
  2. Mit den Pfeiltasten bewegen (die Maus geht hier nicht). Gibt es die Zeile schon (z. B. SMTP_HOST), die vorhandene ändern; sonst ganz unten eine neue Zeile anfangen.
  3. Je Wert eine Zeile: NAME='Wert' – Wert in einfachen Hochkommas, kein Leerzeichen um das =.
  4. Speichern: Strg + O (Buchstabe O), dann Enter.
  5. Schließen: Strg + X.
  6. App neu starten (Abschnitt 4).

Mail-Versand (IONOS Exchange, buchhaltung@)

SMTP_HOST='smtp.exchange2019.ionos.de'
SMTP_PORT='587'
SMTP_USER='buchhaltung@viva-deluxe-reinigung.de'
SMTP_PASS='hier das Passwort des Postfachs'
MAIL_FROM='buchhaltung@viva-deluxe-reinigung.de'

Jede Zeile endet mit ' – fehlt es, startet die App nicht („unterminated quoted value“). Enthält das Passwort selbst ein ', bitte melden.

Testen ohne Kundenrisiko: In der App Einstellungen → E-Mail-Versand prüfen → Test-E-Mail senden. Dort steht auch, ob Test- oder Echtbetrieb eingestellt ist und ob alle Mails an die Testadresse umgeleitet werden.

Nur nach Absprache ändern: APP_ENV und MAIL_TEST_RECIPIENT. Solange APP_ENV='test' steht oder die Zeile MAIL_TEST_RECIPIENT existiert, gehen alle Mails an die Testadresse – kein Kunde bekommt etwas. Für den Echtbetrieb: APP_ENV='live' und die Zeile MAIL_TEST_RECIPIENT löschen. Nie anfassen: DATABASE_URL, DB_PASSWORD, SESSION_SECRET (sonst sind alle abgemeldet und der Bankabruf-Schlüssel muss neu hochgeladen werden).

4. App neu starten / aktualisieren

bash /opt/viva/deploy/update.sh

Holt die neueste Fassung, baut sie und startet neu – 1 bis 3 Minuten. Am Ende steht z. B. … aktualisiert auf 1a2b3c4 …. In dieser Zeit zeigt die App „Die App wird gerade aktualisiert“ – nach dem Neuladen ist alles wieder da. Eingaben, die genau in dem Moment gespeichert wurden, gehen nicht doppelt durch.

5. Prüfen, ob alles läuft

cd /opt/viva/deploy
docker compose --env-file .env.live ps

Es müssen 3 Zeilen mit Up bzw. running erscheinen: db (Datenbank), app (App mit E-Rechnungs-Prüfung KoSIT), caddy (HTTPS). Steht irgendwo Exited oder Restarting → Abschnitt 6.

6. Fehlermeldungen ansehen

cd /opt/viva/deploy
docker compose --env-file .env.live logs --tail 80 app

Zeigt die letzten 80 Meldungen der App. Davon ein Foto oder den Text an mich – vorher prüfen, dass kein Passwort darin steht. Für die anderen Teile app durch db oder caddy ersetzen. Live mitlesen: … logs -f app, beenden mit Strg + C.

7. Sicherungen

Jede Nacht um 02:30 Uhr: Datenbank + alle Dateien nach /opt/viva-sicherung, 14 Tage aufbewahrt.

ls -lh /opt/viva-sicherung            # vorhandene Sicherungen mit Größe und Datum
bash /opt/viva/deploy/backup.sh       # sofort eine Sicherung machen (z. B. vor größeren Änderungen)
Wichtig: Diese Sicherung liegt auf demselben Server. Fällt der Server aus, ist sie mit weg. Deshalb im IONOS-Panel Cloud Backup buchen und den Ordner /opt/viva-sicherung mitsichern lassen. Wiederherstellen nur mit mir zusammen.

8. Passwort eines App-Benutzers zurücksetzen

Normalerweise in der App: Einstellungen → Benutzer → Person → „Einmal-Passwort erzeugen“. Kommt niemand mehr als Admin hinein (z. B. gesperrt nach 5 Fehlversuchen):

cd /opt/viva/deploy
docker compose --env-file .env.live exec app npx tsx src/scripts/reset-password.ts            # Liste der Benutzer
docker compose --env-file .env.live exec app npx tsx src/scripts/reset-password.ts ahmed.chomontek

Es erscheint ein Einmal-Passwort; damit anmelden, danach muss ein neues vergeben werden. Die Sperre ist aufgehoben.

9. Root-Passwort des Servers ändern

Das alte root-Passwort stand im Chat – bitte ändern:

passwd

Neues Passwort zweimal eintippen (unsichtbar). Nur im Passwort-Manager notieren. Geht es vergessen, kann man es im IONOS-Panel unter Server → Aktionen → Passwort zurücksetzen neu setzen.

10. Wenn die App nicht lädt

  1. 2–3 Minuten warten und neu laden – evtl. läuft gerade ein automatisches Update.
  2. Verbinden (Abschnitt 1), dann Abschnitt 5: Läuft alles?
  3. Neu starten: 
    bash /opt/viva/deploy/update.sh
  4. Hilft nichts: Meldungen aus Abschnitt 6 an mich schicken.
  5. Reagiert der Server gar nicht mehr (auch keine Anmeldung): im IONOS-Panel Aktionen → Neu starten. Alle Teile der App starten danach von selbst.

11. Was Sie nie tun sollten

  • Keine Befehle mit rm, docker compose down -v, docker volume rm oder docker system prune – damit werden Datenbank oder Archiv gelöscht.
  • Nichts in /opt/viva von Hand ändern außer deploy/.env.live – die Updates überschreiben es bzw. brechen ab.
  • Keine Passwörter, Schlüssel oder den Inhalt von .env.live in Chats, Mails oder Screenshots.
  • Befehle aus fremden Quellen (Foren, Mails) nur nach Rückfrage.
