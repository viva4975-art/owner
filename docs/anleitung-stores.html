App veröffentlichen: Google Play und App Store

Viva-Deluxe App (de.vivadeluxe.app) · Stand 15.10.2026 · Android-Version 4 (neues Logo, PDFs öffnen)

Für beide Stores brauchst du:
  • Datenschutz-Adresse: https://app.viva-deluxe-reinigung.de/m/datenschutz (öffentlich, schon online – bitte einmal von einem Datenschutzberater gegenlesen lassen)
  • Prüf-Zugang für Google/Apple: In der App einen Test-Mitarbeiter „App Prüfung“ anlegen (z. B. Personalnummer 9999, eigene PIN setzen, einem Test-Objekt zuordnen, einen Einsatz für heute planen). Ohne Zugang lehnen beide Stores ab.
  • App-Icon: mobile-app/resources/icon.png (1024 × 1024, Firmenlogo) bzw. assets/web/app-icon-512.png
  • Bildschirmfotos: 3–5 Bilder vom Handy (Startseite mit Einsätzen, Kalender, Urlaub, Dokumente) – Testdaten, keine echten Namen.

Teil A – Google Play (geht ohne Mac)

  1. Neue Version bauen (wie in anleitung-android.pdf): neueste ZIP vom Branch laden, in mobile-app: 
    npm install
npx cap sync android
    Android Studio → Build → Generate Signed App Bundle / APK → Android App Bundle → derselbe Upload-Schlüssel wie beim letzten Mal → release. Ergebnis: app-release.aab (versionCode 4).
  2. Play Console (play.google.com/console) → App erstellen (falls noch nicht): Name „Viva-Deluxe“, Standardsprache Deutsch, App, kostenlos, Erklärungen bestätigen.
  3. Erst intern testen: Testen → Interne Tests → Neuen Release erstellen → .aab hochladen → Versionshinweis „Neues Logo, PDFs öffnen“ → Tester-Liste (E-Mail-Adressen von dir, Objektleitungen) → Teilnahmelink per WhatsApp schicken. Interne Tests sind in Minuten verfügbar, ohne Prüfung.
  4. App-Inhalte ausfüllen (Menü Richtlinien → App-Inhalte):
    PunktWas eintragen
    DatenschutzerklärungAdresse oben
    App-Zugriff„Alle oder einige Funktionen sind eingeschränkt“ → Anleitung: „Personalnummer 9999, PIN …, auf ‚Anmelden‘ tippen“
    WerbungNein
    EinstufungFragebogen: Kategorie „Dienstprogramm/Produktivität“, alles „Nein“ → USK 0
    Zielgruppe18 Jahre und älter
    DatensicherheitErhoben: Name, E-Mail, Telefon, genauer Standort (nur beim Stempeln, wenn eingeschaltet), Fotos, App-Aktivität (Arbeitszeiten), Geräte-ID für Mitteilungen. Zweck: App-Funktionen. Nicht an Dritte weitergegeben. Übertragung verschlüsselt: Ja. Löschung: auf Anfrage über die Firma.
    Behörden-/Gesundheits-AppsNein
  5. Store-Eintrag (Wachstum → Store-Präsenz → Haupteintrag): Kurzbeschreibung „Zeiterfassung, Einsätze und Dokumente für das Team der Viva-Deluxe Gebäudereinigung“, ausführliche Beschreibung (Hinweis: „Nur für Beschäftigte, Zugang über die Firma“), Icon 512 × 512, Vorstellungsgrafik 1024 × 500 (Logo auf Weiß/Bordeaux), mind. 2 Bildschirmfotos, Kategorie Business, Kontakt-E-Mail.
  6. Veröffentlichen: Produktion → Länder: Deutschland → Neuen Release erstellen → denselben .aab aus dem internen Test übernehmen → Zur Überprüfung senden. Prüfung meist 1–7 Tage.
Euer Entwicklerkonto läuft auf die GmbH (D-U-N-S). Die Pflicht „12 Tester × 14 Tage geschlossener Test“ gilt nur für private Konten – für euch nicht. Falls die Console sie trotzdem verlangt: Geschlossener Test mit 12 Kolleginnen/Kollegen 14 Tage laufen lassen.
Die App ist im Store auffindbar, nutzen kann sie nur, wer von uns einen Zugang hat. Ganz unsichtbar („private App“) ginge nur über Managed Google Play mit Google Workspace – für euch nicht nötig.

Teil B – Apple App Store

Wichtig: Eine iPhone-App kann nur auf einem Mac mit Xcode gebaut und hochgeladen werden. App Store Connect allein reicht nicht. Ohne eigenen Mac: Mac leihen oder einen Miet-Mac in der Cloud (z. B. MacinCloud, ca. 30 €/Monat) nutzen. Das iOS-Projekt ist noch nicht angelegt – das geht nur auf dem Mac (Schritt 3).
  1. Bundle-ID registrieren (developer.apple.com → Certificates, IDs & Profiles → Identifiers → + → App IDs → App): Beschreibung „Viva-Deluxe“, Bundle ID explicit de.vivadeluxe.app, Capability Push Notifications anhaken.
  2. App in App Store Connect anlegen (appstoreconnect.apple.com → Apps → + → Neue App): Plattform iOS, Name „Viva-Deluxe“ (falls vergeben: „Viva-Deluxe Team“), Primärsprache Deutsch, Bundle-ID aus Schritt 1, SKU vivadeluxe-app, Benutzerzugriff „Voller Zugriff“.
  3. Auf dem Mac: Xcode aus dem App Store installieren, Node.js installieren, Projekt-ZIP laden, im Terminal in mobile-app: 
    npm install
npx cap add ios
npx cap sync ios
npx cap open ios
    In Xcode: links App → Signing & Capabilities → Team = eure GmbH, Bundle Identifier de.vivadeluxe.app. Assets → AppIcon: mobile-app/resources/icon.png hineinziehen. In Info zwei Texte ergänzen:
    SchlüsselText
    Privacy – Camera Usage DescriptionZum Scannen des QR-Codes am Objekt und für Fotos der Qualitätskontrolle.
    Privacy – Location When In Use Usage DescriptionNur beim Ein- und Ausstempeln, um zu prüfen, ob du am Objekt bist.
  4. Hochladen: oben als Ziel Any iOS Device wählen → Product → Archive → Distribute App → App Store Connect → Upload. Nach ca. 15 Minuten erscheint der Build in App Store Connect unter TestFlight → dich und die Objektleitungen als interne Tester eintragen und auf dem iPhone mit der App „TestFlight“ testen.
  5. Angaben in App Store Connect:
    BereichWas eintragen
    App-InformationenKategorie Business, Altersfreigabe-Fragebogen (alles „Nein“ → 4+)
    App-DatenschutzDatenschutz-Adresse oben; Datenarten wie bei Google (Kontakt, Standort genau, Fotos, Nutzungsdaten, Geräte-ID) → „mit der Identität verknüpft“, nicht für Tracking
    PreiseKostenlos, Verfügbarkeit Deutschland
    Version 1.0Bildschirmfotos 6,7" bzw. 6,9" iPhone (Pflicht), Beschreibung, Schlüsselwörter, Support-URL https://www.viva-deluxe-reinigung.de, Build aus TestFlight auswählen
    Informationen zur App-PrüfungAnmeldedaten des Prüf-Zugangs (Personalnummer/PIN) und Hinweis: „Interne App für Beschäftigte der Viva-Deluxe Gebäudereinigung GmbH; Zugang wird von der Firma vergeben.“
  6. Zur Prüfung einreichen. Prüfung meist 1–3 Tage.
Risiko Ablehnung (Richtlinie 4.2 / 3.2): Apple lehnt reine „Webseiten in einer Hülle“ und Firmen-Apps für einen geschlossenen Nutzerkreis manchmal im öffentlichen Store ab. Dann: „Unlisted App“ beantragen (Formular bei Apple „Unlisted app distribution request“ – App ist nur über Link installierbar) oder als Custom App über Apple Business Manager verteilen. Bis dahin: iPhone-Nutzer nehmen die Web-App (Safari → Teilen → „Zum Home-Bildschirm“) – Mitteilungen gehen dort ab iOS 16.4 auch.

Bei jedem Update

Inhalt und Funktionen kommen vom Server – dafür ist kein neuer Store-Upload nötig. Neu hochladen nur, wenn sich Logo, Name, Berechtigungen oder der native Teil ändern (Android: versionCode in mobile-app/android/app/build.gradle um 1 erhöhen; iOS: Build-Nummer in Xcode erhöhen).
